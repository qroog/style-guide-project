# SQL и работа с данными

Раздел описывает оформление SQL-запросов, миграции и работу с данными. Примеры даны для PostgreSQL.

## Регистр и отступы (Q-01)

**Правило.** Ключевые слова пишите прописными буквами, имена — строчными в `snake_case`. Каждую основную часть запроса начинайте с новой строки. Отступ — 4 пробела.

```sql
SELECT
    o.id,
    o.created_at,
    u.email
FROM orders AS o
JOIN users AS u ON u.id = o.user_id
WHERE o.status = 'paid'
ORDER BY o.created_at DESC;
```

**Проверка:** sqlfluff.

## Не используйте SELECT * (Q-02)

**Правило.** В коде приложения перечисляйте нужные столбцы. Так запрос не ломается при изменении таблицы и не передаёт лишние данные.

## Явные соединения и алиасы (Q-03)

**Правило.** Используйте явный `JOIN … ON`, а не соединение через запятую. Алиасы задавайте через `AS`, они должны быть осмысленными.

## Параметризованные запросы (Q-04)

**Правило.** Никогда не собирайте SQL из пользовательского ввода конкатенацией. Передавайте значения параметрами (`$1`, `$2`).

**Почему.** Конкатенация приводит к SQL-инъекциям.

```go
// Плохо
q := "SELECT id FROM users WHERE email = '" + email + "'"

// Хорошо
row := db.QueryRowContext(ctx, "SELECT id FROM users WHERE email = $1", email)
```

## Миграции (Q-05)

**Правило.** Изменения схемы вносятся только через версионируемые миграции (например, `golang-migrate` или `goose`). Применённую миграцию не редактируйте: создавайте новую.

## Обратимость миграций (Q-06)

**Правило.** У каждой миграции есть шаги `up` и `down`. Необратимые изменения (удаление данных) помечайте комментарием в первой строке файла.

## Индексы (Q-07)

**Правило.** Создавайте индексы для внешних ключей и столбцов частых фильтров. Эффект нового индекса подтверждайте командой `EXPLAIN ANALYZE`.

## Транзакции (Q-08)

**Правило.** Держите транзакции короткими. Операции, которые должны выполниться вместе, выполняйте в одной транзакции. В Go сразу после начала транзакции добавляйте `defer tx.Rollback()`.

## Типы данных (Q-09)

**Правило.** Время храните в `timestamptz` в UTC. Деньги — в `numeric`, а не в `float`. Идентификаторы — `bigint` или `uuid`. Ограничения `NOT NULL` и `CHECK` задавайте по умолчанию.

## Изменение и удаление данных (Q-10)

**Правило.** Перед массовым `UPDATE` или `DELETE` выполните `SELECT` с тем же условием `WHERE`, а сам запрос запускайте в транзакции. Если данные нужно восстанавливать, используйте мягкое удаление (`deleted_at`).

## Персональные данные (Q-11)

**Правило.** Собирайте минимум данных, маскируйте их в логах. Не используйте продуктивные данные в тестах и на локальных стендах.

## Комментарии в SQL (Q-12)

**Правило.** Для неочевидных запросов добавляйте комментарии `--`, для таблиц и столбцов — `COMMENT ON`.

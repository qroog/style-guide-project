# Заведение задач в YouTrack

Раздел описывает, как создавать и вести задачи в YouTrack. Названия типов, полей и состояний зависят от настройки вашего проекта; ниже приведён типовой набор, при необходимости адаптируйте его.

## Одна задача — один результат (Y-01)

**Правило.** Задача описывает один проверяемый результат и занимает не более двух дней работы. Крупную работу оформляйте как Epic с подзадачами.

## Заголовок (Y-02)

**Правило.** Заголовок начинается с глагола, содержит объект и контекст, до 80 символов. Не используйте заголовки `Не работает` и `Баг`.

| Плохо | Хорошо |
|---|---|
| `Баг в заказах` | Исправить расчёт скидки в корзине при пустом промокоде |

## Тип и приоритет (Y-03)

**Правило.** Выберите тип: Bug (ошибка), Feature (новая функция), Task (техническая работа), Epic (крупная цель). Приоритет выбирайте по влиянию на пользователей: Show-stopper, Critical, Major, Normal, Minor.

## Структура описания (Y-04)

**Правило.** Описание задачи содержит четыре части: контекст (зачем), что нужно сделать, критерии приёмки, ссылки (макеты, документы, связанные задачи).

```markdown
## Контекст
Пользователи не видят статус доставки.

## Что нужно сделать
Добавить поле `delivery_status` в ответ API и на страницу заказа.

## Критерии приёмки
- [ ] API возвращает `delivery_status`
- [ ] Статус отображается на странице заказа
- [ ] Добавлены тесты и обновлена документация API

## Ссылки
Макет: <ссылка>
```

## Описание ошибки (Y-05)

**Правило.** Для Bug укажите: шаги воспроизведения, ожидаемый результат, фактический результат, окружение (версия, ОС, браузер), логи или скриншот.

```markdown
## Шаги
1. Добавьте товар в корзину.
2. Оставьте поле промокода пустым.
3. Нажмите **Оформить заказ**.

## Ожидаемый результат
Скидка не применяется, заказ оформлен.

## Фактический результат
Ошибка 500, в логе `invalid promo code`.

## Окружение
Версия 1.4.2, Chrome 130, Windows 11.
```

## Критерии приёмки (Y-06)

**Правило.** Критерии проверяемы: по каждому можно ответить «выполнено» или «не выполнено». Оформляйте их чек-листом.

## Обязательные поля (Y-07)

**Правило.** При создании заполните: проект, тип, приоритет, подсистему, оценку трудозатрат. Исполнителя назначайте, когда работа берётся в спринт.

## Связь с Git (Y-08)

**Правило.** Ключ задачи (например, `PROJ-123`) указывайте в имени ветки, в теле коммита и в описании pull request. Так задача связывается с изменениями кода (при настроенной интеграции YouTrack с VCS).

## Состояния (Y-09)

**Правило.** Актуализируйте состояние сразу при смене работы. Типовой путь: Open → In Progress → In Review → Done (или Verified).

## Поиск дубликатов (Y-10)

**Правило.** Перед созданием задачи найдите похожие. Дубликат закройте и свяжите ссылкой на исходную задачу.

## Комментарии в задаче (Y-11)

**Правило.** Комментарии пишите по делу. Принятое решение и причину фиксируйте комментарием, а не только в чате.

## Закрытие задачи (Y-12)

**Правило.** Задача закрывается, когда выполнены критерии приёмки, pull request слит, а результат проверен. Закрывает исполнитель или проверяющий.
